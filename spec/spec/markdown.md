# Markdown

The body of a document is everything after the closing `---` of the front matter. The tool reads headings, HTML comments, code blocks, HTML blocks and links throughout it, blockquotes and list items as far as they hold those blocks, blockquotes within the question sections, and list items within a `Changelog` section. Everything else is text. A carriage return before a line feed is part of the line ending, and a construct is recognised in a CRLF file exactly as in an LF one. A body longer than 131,072 bytes is not read: the tool finds no heading, section, anchor, link, question, entry or definition in it.

## Headings

Headings are read from the body's outline, as goldmark parses it: ATX headings, `#` through `######` at most three spaces in, and setext headings, the lines of a paragraph followed by a line of `=` or `-`. A heading of nothing but a closing sequence, such as `## #`, is empty. A heading's text is its content, without its markers, closing sequence or underline, a setext heading's lines joined by a line feed, with each HTML comment in it replaced by spaces and its ends trimmed. A line that is a heading only once a comment on it is masked, such as `##<!-- c --> Proposal`, is a paragraph. A top-level heading, one that no blockquote, list item or footnote definition holds, bounds a section and opens a `contents` entry; a heading inside one has an anchor and does neither. The body after a heading starts on the line after its last, a setext heading's underline. The block count of a term's definition reads each line as written, an ATX heading by its marker.

The first top-level heading is an H1 of the form `<id>: <title>` for a numbered type, or `<title>` for a spec page, a term or a group.

## Anchors

Every heading has an anchor, computed as GitHub computes it, from the heading's pieces as goldmark reads them, rendered to text: a text with its backslash escapes and HTML entities resolved, a code span's content, a link's text, an autolink's address as written, an address the linkify extension finds included, a footnote reference's number, and nothing for an image or raw HTML, a comment included. Emphasis, strong emphasis and strikethrough render as their text, and a delimiter goldmark pairs with nothing is text, so `## The _id field` keeps its underscore. The text is lowercased, everything that is not a letter, mark, decimal digit, letter number, connector punctuation, hyphen or space is removed, and each space becomes a hyphen: `Ⅻ` is kept, and `²` and `½` are removed. `## <!-- note --> Scope` anchors as `-scope`, and `## The [RFC-0007](path) approach` as `the-rfc-0007-approach`. Anchors are assigned in the order GitHub renders the headings: each heading outside a footnote definition, in document order, then the headings of each footnote definition in the order its label is first referenced, a footnote reference numbered in the same order. A definition that nothing references is not rendered, and its headings have no anchor. A heading whose anchor is already taken within the document gains a `-1`, `-2` suffix. A heading in isolation has no anchor. An explicit anchor is the `id` or `name` of an `<a>` start tag in raw HTML or an HTML block, outside comments, its entities resolved; one in a footnote definition that nothing references is not read. Where goldmark reads a heading otherwise than cmark-gfm, as for a known difference `testdata/commonmark/KNOWN` lists, the anchor is made from goldmark's reading.

## Links

Links are read from the body's outline, as goldmark reads them: an inline link `[text](destination)`, an image `![text](destination)`, and a link reference definition `[label]: destination`, wherever goldmark reads one, in blockquotes, list items, table cells and footnote definitions included, and never in a code span, a code block or an HTML block. Where goldmark reads a link otherwise than cmark-gfm, as for a known difference `testdata/commonmark/KNOWN` lists, the tool reads goldmark's link. A link's text is its bytes as written between its brackets, its lines joined by a line feed with any quote markers and indentation, and each HTML comment in it replaced by spaces. Its destination is the one goldmark gives, escapes and entities resolved, percent-decoded where it decodes. Its position is that of the destination as written, within any `<` and `>`, and the link is on the line holding it. An empty destination, as in `[text]()`, starts and ends after the `(`.

A label beginning `^` is a footnote, and a footnote definition is not a link reference definition. `[text][label]`, `[text][]` and `[text]` are reference links where the label, or the text for the last two, matches a definition as goldmark matches them. A reference link is not listed among a document's links; its definition is, and the reference is listed among the document's references, with its definition's destination, on the line holding its text's closing bracket. An autolink is not listed.

A `[[...]]` link is read from text as written, its pieces adjacent, so one holding emphasis, a code span or an entity is none: `[[`, a name holding no `[` or `]`, and `]]`, on one line, within text outside a link's or an image's text. A bracket escaped by a backslash ends none, so `\[[a]]` is no `[[...]]` link, and where the document defines the label inside, as in `[[RFC-0007]]` beside `[RFC-0007]: path`, goldmark reads a link within brackets and there is no `[[...]]` link. A `[[...]]` link in a heading is read, and marked as in one.

The tool's own walk of the lines, which questions, a term's definition, the masking of comments for both, and whether a block is left open when the body ends still read, reads blocks as follows. A paragraph ends at a blank line, a code block, an HTML block, a heading, a list item able to interrupt it, a table, a thematic break, a setext underline and the first line of a blockquote; a quote's later lines continue it. A heading, like every other block, is read past the markers of the blockquotes and list items holding the line, so `    # x` continues the paragraph above it; a block's marker is indented at most three columns past them, a tab running to the next multiple of four and a tab the markers take part of leaving the rest as indentation. A table begins at a line followed, within the same blockquotes and list items, by a delimiter row of as many cells, such as `| - | :-: |`, indented at most three spaces past their markers, that is not a list item or a setext underline. A paragraph holding a line followed by a delimiter row of another number of cells begins no table after it. Cells are parted at every `|` but one straight after a backslash, one inside a code span or a comment included, and a `|` at either end of a row opens or closes it, so a row of a lone `|` has no cells and begins no table. A table runs to a line with no cells, a blank one among them, or the start of another block, a lone HTML tag included, and each of its rows and cells is read on its own: a code span or a comment does not run from one cell into the next. A line beginning `|` with no delimiter row beneath it is text.

## Sections

A section is a top-level H2 and everything after it, up to the next top-level heading of equal or higher level. It includes its own subsections. A section is empty if it holds nothing but whitespace and HTML comments.

Section presence is checked by exact H2 text. The required sections by type:

- RFC: `Abstract`, `Motivation`, `Proposal`, `Alternatives considered`, `Backwards compatibility`, in that order. `Rejection rationale` is required when the status is `rejected` and forbidden otherwise. `Sources` is required when `backfilled` is set. A document requiring either has a closing section that is its last H2: `Rejection rationale` when rejected, `Sources` otherwise. A document requiring neither may carry extra sections after the required ones.
- ADR: `Context`, `Decision`, `Alternatives`, `Consequences`, in that order. `Rejection rationale` and `Sources` as for an RFC.
- Ref: `Sources` is the last H2.
- Spec: no requirements.
- Term: no required sections. The definition is everything after the H1 to the end of the file, and L15 wants it to be exactly one paragraph.
- Group: no required sections. Its description is the body after the H1.

Extra H2 sections are permitted between or after the required ones. `Open questions`, `Resolved questions` and `Changelog` are optional for every type, and are read as described below wherever they appear.

## Questions

The question sections are H2s titled `Open questions` and `Resolved questions`. A question is an H3 within one, and its text is the question. Its detail is the lines after it, to its answer or to the next top-level heading. A document carries at most one `Resolved questions` section, and where it has an `Open questions` section, `Resolved questions` is the next H2 or H1 after one.

Within a question section, a blockquote is a run of consecutive lines each beginning with `>` at the start of the line, outside an HTML comment and any code block or HTML block the blockquote does not hold. A question ends with a blockquote when its last one is followed by nothing but blank lines and comments before the next heading or the end of the document. In `Resolved questions`, that blockquote is the question's answer: its lines with the `>` and one column of the whitespace after it removed from each, a tab after the marker leaving two spaces.

An `Open questions` section is empty or holds questions and nothing before the first. A `Resolved questions` section holds at least one question and nothing before the first. No question has a heading beneath it, and no blockquote in a question section holds a heading, a fenced code block or an HTML comment. An open question does not end with a blockquote. A resolved question ends with a non-empty one, with no other blockquote before it separated by only blank lines and comments. No question's heading produces an empty anchor, or the same anchor as another heading in the document, compared before any suffix is added.

## Changelog entries

A `Changelog` section runs from the line after its H2 to the next top-level H1 or H2. A carriage return before a line feed is removed before a line of it is read, and a blank line holds nothing but spaces and tabs.

An entry line begins `- ` at column 0 with a character other than a space or a tab after the space, and is not a line made only of three or more `-`, spaces and tabs. A block opener is a line beginning `#`, `>`, `<`, `-`, `*`, `+`, `_`, `=`, `|`, `[`, a backtick or `~`, or digits followed by `.` or `)`. After an entry line, each line in turn belongs to the entry while it is indented by two or more spaces with no tab before its first non-blank character; or blank, where a later line belongs to the entry; or a line at column 0 that is neither blank nor a block opener, directly after the entry line or another such line, where what follows the entry line's `- ` is not a block opener either. The first other line ends the entry.

Comment lines run from a line beginning `<!--` at column 0 outside every entry to the first line, starting with that one, that holds `-->`, where that line ends with `-->`. A line within them is not an entry line. Every line of the section that is not in an entry, blank or within comment lines belongs to no entry.

An entry's date is four digits, two and two, separated by `-`, directly after `- `, followed by `:` and then a space or the end of the line, that is a real calendar date. An entry without one is undated. Its text is its lines with `- ` and any date, its `:` and one space removed from the first, the first two spaces removed from each later line indented by two or more, and blank lines at either end dropped. A nested item is text within its entry.

Entries are read from every `Changelog` section, in document order. A level two heading differing from `Changelog` only in case, spacing or punctuation is not a `Changelog` section.

## Comments

Text inside an HTML comment is not content anywhere. It is passed over when finding headings, sections, links and `[[...]]` links, and when suggesting them. A comment opening a block, its `<!--` at most three columns in, a tab running to the next multiple of four, runs to the first line holding `-->`, or to where the blockquote or list item holding it ends, or to the end of the document where neither comes first; nothing after its `-->` on that line opens another comment, and a comment block closing on the line it opens leaves no paragraph open after it. A `<!--` elsewhere in a paragraph opens a comment only where a `-->` follows it before its paragraph ends, and is text otherwise; a paragraph ends at a line that is blank once its containers' markers are passed, that is a setext underline other than a lazy continuation line, or that starts a block able to interrupt one, read in the blockquotes and list items it continues. A `<!--` in a heading opens a comment only where a `-->` follows it on the heading's line, and one in a table row only where a `-->` follows it in its cell, and is text otherwise. `<!-->` and `<!--->` are complete comments, the `-->` sharing the dashes of the `<!--`. A paragraph holding a comment continues past it, so a line after the comment indented four columns continues the paragraph. A `<!--` after an odd run of backslashes is text. Text sharing a line with a comment that does not open a block, before its `<!--` or after its `-->`, is content. The line holding the `-->` of a comment opening a block is the block's last line: text after the `-->` is content, as an HTML block's is, and holds no heading, link, `[[...]]` link or comment. The line after it is read as written.

## Code and HTML blocks

A fenced code block opens on a run of three or more backticks or tildes at most three columns in. A backtick fence's info string holds no backtick, so ```go``` opening a line is a code span. The block closes on a run of the same character at least as long, at most three columns in, carrying no info string, or where the blockquote or list item holding it ends. An indented code block is a run of lines indented four or more columns, a tab running to the next multiple of four, that does not continue a paragraph (a setext underline, a run of `=` or `-` alone at most three columns in, ends the paragraph above it), and ends at the first line indented less.

An HTML block opens a line, at most three columns in. One opening with `<script`, `<pre`, `<style` or `<textarea` closes on the line holding any of `</script>`, `</pre>`, `</style>` or `</textarea>`; with `<?`, `<![CDATA[` or `<!` and an uppercase letter, on the line holding `?>`, `]]>` or `>`, which may be the line it opens on, `<?>` included. One opening with a tag of a block-level HTML element, or outside a paragraph with any single complete tag alone on its line other than an opening tag of one of those four, closes before the next blank line.

Blocks are read inside blockquotes and list items. A line continues a blockquote behind its `>` and a list item while indented to the item's content, or lazily, as a paragraph's continuation that starts no block. A blank line continues a list item only once the item holds something, so an item can begin with at most one blank line. A list item interrupts a paragraph in its own container only if it is not empty and, when numbered, starts at 1; a line that does not continue the paragraph's container starts a list item of any number, or an empty one. A block inside one ends with it.

Nothing inside a code block or an HTML block is prose. It holds no heading, link or `[[...]]` link, opens no comment, and is content. A `<!--` or `-->` inside an inline code span is literal, the span read across the lines of its paragraph or within its cell of a table row, and a fence marker inside a comment is literal: whichever block opens first holds the lines until it closes. A code span closes on a backtick run of exactly the length that opened it, and may run across the lines of one paragraph.

## Masking

A body is read through masked copies of its lines, each the same length as the line as written and differing from it only where a byte became a space, so a position in one is the same position in the other. Masked text is never shown.

- Comment-masked text blanks each HTML comment in an HTML block, one left open running to the block's end. A section's emptiness is read from it.
- Prose text blanks every byte but those of text that is prose, and holds no line of a code block or an HTML block. Text is prose where it is not in a heading, not within a link's or an image's text, not between an `<a` start tag and its `</a>` in the same paragraph or table cell, not part of an address with a scheme or beginning `www.`, from its start to the next space, and not between a `[` and the `]` closing it on its line. A code span, raw HTML and a link reference definition are not text. Suggestions are offered within prose text.
- The walk's masked text blanks comments as Comments describes, and questions and a term's definition are read from it.
