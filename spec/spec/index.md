# Index

`archdoc index` generates `INDEX.md` under `root` and prints the path written. With `--check`, it generates to memory, prints a unified diff where the result differs from the file on disk, and exits 2; where they match it prints nothing and exits 0. With `--json`, a difference is reported as a single finding against `INDEX.md` and no diff is printed.

## Format

```markdown
# <name> index

Generated by ArchDoc. Do not edit.

## RFCs

| ID | Title | Status | Decided | Updates | Updated by | Obsoletes | Obsoleted by | Implemented in |
|---|---|---|---|---|---|---|---|---|

## ADRs

(same columns)

## Spec

| Page | Title | Includes | Stale |
|---|---|---|---|

## Refs

| ID | Title | Verified |
|---|---|---|
```

All four sections are always present with their header rows, even when empty. Rows are sorted by identifier for numbered types and by path for spec pages. Every identifier and page in every cell is a relative Markdown link. Empty cells are empty. A status carries its qualifiers in parentheses, comma-separated, in the order backfilled then obsolete: `accepted (backfilled)`, `accepted (obsolete)`, `accepted (backfilled, obsolete)`. `Stale` is `yes` or empty. `Implemented in` lists the spec pages including the document. Terms are not listed: `GLOSSARY.md` is their index.

Every cell is escaped and every link destination is percent-encoded, so a title or filename containing a pipe, a bracket, an angle bracket or a parenthesis cannot alter the table.
